Hybrid: decentralized, with a net.

Every robot runs its own full autonomy stack and coordinates only over the radio — there is no central oracle in the control loop. A central task manager sits beside that loop for global oversight and a fallback path, not inside it.

Per robot, and fleet-shared

The graph divides cleanly. Each robot owns a perception → SLAM → Nav2 chain and an explorer. A small set of nodes runs once for the whole fleet: the 2D and 3D map mergers, and the radio. Toggle the views:

Decentralized, with central oversight

The coordination layer is fully decentralized — no robot depends on a central planner to move, and the fleet keeps working if the task manager drops. What the central task manager adds is a global view: queue health, run oversight, and a fallback allocation path when peer-to-peer coordination degrades. It shares the single navigate_to_pose server with the explorer, so the two arbitrate rather than fight.

Not a colcon workspace

The repository is deliberately not a standard robotics workspace. There are no packages; every node is a loose script under nodes/, launched by path from one bringup file. Tuning is plain YAML loaded by each node, not ROS params (except Nav2, which keeps configs/nav2_params.yaml). Offline unit tests import the ROS-free cores directly — map_fuse.py, recon_fuse.py, the radio's encode/parse — so the fusion maths and the protocol are testable in seconds with no sim.

Two simulator tracks

Isaac Sim and ROS 2 must never share a shell, and the two simulation tracks share no code.

Isaac Sim — mobility

  • Warehouse scene, multi-robot spawn
  • RGB-D + IMU + odom into ROS 2
  • RTAB-Map SLAM, Nav2, exploration
  • NVIDIA packages (Nvblox)

ManiSkill / XLeRobot — manipulation

  • ReplicaCAD apartment scene
  • Dual-arm control modes, teleop
  • Teleop dataset recording → imitation learning
  • Headless RGB / sensor rollouts for RL

The control plane

A console process outlives individual sim runs so the dashboard's Scenarios tab can start and stop them. Everything the tab does is also one command through scripts/sim_ctl.sh, with exit codes as the interface.

CodeMeaning
0success
1command failed (bad scenario, rejected start, run went to failed)
3no console running
4no session running — how you ask "is anything running?"
124timed out waiting for a phase

Field notes

Diagnosed live · 2026-08-01

Reliable image subscribers kill the simulator

Repeatedly subscribing to camera topics with reliable delivery — the default, which an ad-hoc command-line subscription will happily do — silently kills the simulator's image writers about two minutes into a run. The cameras just stop, with no error. Every snapshot request must ask for sensor-data QoS explicitly. Bisected live: Isaac alone is stable indefinitely; only the churn of reliable snapshot subscriptions correlates with the death.

Field note

Measure speed in simulated time

The simulation runs at roughly 0.45× real time, and not consistently. Every speed and duration figure in this project is measured against the simulated clock; a wall-clock stopwatch reports numbers wrong by more than a factor of two.
