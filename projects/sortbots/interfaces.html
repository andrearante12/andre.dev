An operator, a camera, and two arms.

Between the autonomy stack and the world sit three things a person actually touches or sees: the dashboard an operator drives the fleet from, the vision that reads a package and names an obstacle, and the arms that lift the box off the shelf.

The dashboard

A React web GUI is the operator's whole interface to the fleet. It takes task input — pickup and dropoff, dispatched into the shared queue — and shows live robot state: camera feeds, the fused 2D map with Nav2 path and costmap overlays, and the 3D reconstruction. It is served over plain HTTP on the private tailnet so a phone on the same network can drive it.

A headless control plane mirrors every dashboard action: scripts/sim_ctl.sh {console start | list | start | wait | status | stop}, with exit codes as the interface, so automation and coding agents drive the same operations without hand-writing JSON.

Computer vision

Two jobs, both on the head camera. Package identification reads an ArUco marker or a barcode on the box to resolve which item and which destination — the link between a physical package and a queue entry. Obstacle classification runs YOLO on the RGB frame to label what the depth camera already flagged as a mover: person or other robot. The class changes the response — a person gets a wider berth and a longer clear-timeout than a peer robot, which the radio already accounts for.

Manipulation

Two arms, six joints. Getting to the shelf is a navigation problem; at the station, arm control solves inverse kinematics with MoveIt 2 for an autonomous pick-and-place. The robot docks a fixed offset short of the deck and slightly off-centre — the arm is mounted a few centimetres off the chassis centreline — so the reach envelope lines up with the shelf face.

The pick sequence — stow, approach, descend, close, attach, lift, carry — is streamed as joint commands at 20 Hz. task_manager requests a pick, the arm controller drives the joints and signals a simulated grasp, and reports picked / placed / failed back to the queue.

Field notes

Field note

A top-level import that made the node unlaunchable

The arm node imported the IK backend at module scope. That dependency only exists in the manipulation project's separate environment, so in the mobility environment the import failed instantly and no launch file could ever start the node. Nothing was subscribed to pick requests, so every dispatched task sat in the picking state until it timed out, with no error pointing at the cause. The solver now lives behind a flag with lazy imports.

Field note

Joint limits are a hint to the solver, not a constraint

The IK library accepts joint limits but treats them as a suggestion — it returned a 4.33 rad solution for a joint whose range ends at 3.45. Every solution is re-checked against the limits on the caller's side before it is accepted.
